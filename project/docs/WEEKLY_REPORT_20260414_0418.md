| 阶段 | 名称 | 核心设置（简述） | 主要目的 |
|------|------|------------------|----------|
| **AP0** | AVT standard 满程（可选留档） | `fusion_strategy: standard`，**noDA**，三数据集混合，**50 epoch**，`seed: 3407`；配置 `ap0_AVT_noDA_standard_full50_s3407.yaml` | 在 **accuracy_seq** 目录下与 AP2/AP3 **同一 metrics 口径** 留一条 standard 对照；与 `logs_rerun` 对比时须标注数据来源 |

### 3.4 效果评价与现象说明

- **总体**：在混合三数据集、统一 7 类验证设定下，本 run 的 **Best Val Acc 约 0.32**，处于指南所述混合验证常见量级区间；**Best 出现在训练极早期（epoch 1–2）**，提示后续 **AP2 配方消融**（有效 batch、学习率、采样与损失形式）仍有较大优化空间。  
- **异常现象（需后续复核）**：自 **epoch 11 起至 epoch 49**，验证集 **accuracy / precision / recall / f1 长时间保持同一数值**，在真实混淆矩阵频繁变化的情况下较少见。建议后续结合 **`checkpoint_pretrain_best_f1.pth`**、**`recompute_val_metrics.py`** 或抽样 batch 复核，排除评估缓存、固定预测或记录逻辑导致的**指标平台期假象**。  
- **与下周衔接**：实验侧按指南推进 **AP1 → AP2 → …**；工程侧 **优先完成 `emotion-agent` 前后端架构调通（mock 闭环）**，再并行或顺延 AP1/AP2；资源上继续遵循 **AVT 全模态每卡单任务优先**，避免 OOM。

## 四、工程主线：情感智能体框架（`emotion-agent`）

### 4.1 智能体总体架构（依据工程方案文档）

[`EMOTION_AGENT_ENGINEERING_PLAN.md`](EMOTION_AGENT_ENGINEERING_PLAN.md) 将系统定位为 **「离线训练稳定 + 在线推理闭环」**：**摄像头 / 麦克风** 与 **ASR 文本** 经实时预处理与时间对齐后，由 **滑窗样本构建器**（建议首版 **3.0 s 窗、1.0 s 步**，视频每窗约 **8 帧**，文本取窗内 ASR 拼接并设占位兜底）形成三模态输入；送入 **多模态情感模型服务** 得到 **情绪标签、置信度、valence/arousal、全类概率及降级标记**；再经 **LLM 编排层** 按置信度分级（高 / 中 / 低）生成 **安慰 / 鼓励 / 冷静 / 风险提示** 等话术，并强制 **低置信安全模板**；结果同步到 **Web UI** 与 **实验日志**，便于演示与论文案例导出。服务侧建议拆分为 **emotion-service、asr-service、agent-service、web-ui**；与 `project` 的对接通过 **适配层** 调用既有 `inference` 能力，**不侵入训练主链路**。

### 4.2 目标对齐文档

落实 [`EMOTION_AGENT_ENGINEERING_PLAN.md`](EMOTION_AGENT_ENGINEERING_PLAN.md) 中的 **离线训练与在线推理解耦** 思路：采集与编排在新工程完成，**不修改** `project/scripts/train.py` 主训练链路；情感模型通过 **适配器（adapter）** 接入，便于训练效果不理想时切换实现。
