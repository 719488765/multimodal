## 零、重跑设计、动因与本周调度（建议单独 1 页或并入「本周概述」）

### 0.1 设计要点

- 本轮将日志、检查点与输出与历史实验分开存放，配置单独成册，实验命名统一带重跑前缀，便于论文写清数据来源和复现条件。
- 主线顺序强调可比性：先音频+文本无域适应基线，再域适应对照，再引入视频，最后做全模态无域适应、全模态域适应，以及融合策略对照；各任务用独立后台会话管理，一键按顺序拉起。
- 结果固化：除按验证损失保存最优模型外，另存验证 F1 最优模型；定稿前对关键模型用统一脚本在验证集上重算指标，避免只看训练落盘数值。

### 0.2 为何组织本轮重跑

- 上一轮主实验批次混杂，口径与代码版本不完全对齐，难以单独说明「修复后」基线是否可靠。
- 曾存在验证集指标计算实现问题（入参顺序错误），导致精确率、F1 等不可直接采信；已在上一轮周报说明并在代码中修复。本轮重跑在修复后的链路上重新记录，并与重算结果交叉核对。
- 工程上：历史日志已归档；训练脚本增加 F1 最优检查点；重跑前先做短程冒烟，降低标签映射等隐性风险。

### 0.3 本周 GPU 调度与全模态任务

- 本周多任务并行占用显存，「全模态、emotion_shift 融合」一度排队，尚未形成可用验证曲线。
- 「全模态、无域适应」（三模态预训练、无域适应）在资源允许后已启动，目前仅有短程验证记录（个位数 epoch 量级），与「全模态域适应」短程同属过程数据，本周不写终局结论。
- 策略：优先保障已在跑的主线；emotion_shift 待前述任务释放算力后再启，避免显存争用。

### 0.4 本周效果小结

- 已闭环：音频+文本、三数据集、无域适应，50 个 epoch 跑满，曲线完整，可作为修复后口径下的主基线证据之一。
- 进行中：音频+文本域适应、视频+文本无域适应、全模态域适应、全模态无域适应均有短程验证曲线，未满程，本周不写最终结论。
- 待补齐：全模态 emotion_shift 本周仍无有效曲线；论文若需该设定数字，暂引用历史主批次或待补跑后统一口径。
