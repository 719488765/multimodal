### 2.4 AP2 结果（配方消融，三混合）

| AP2 配方 | Last Acc / F1 | Best Acc（epoch） | Best F1（epoch） | 相对基线结论 |
|----------|----------------|-------------------|------------------|--------------|
| baseline | 0.582595 / 0.532011 | 0.590921（9） | 0.532011（12） | 基线 |
| M1（effbatch8） | 0.560301 / 0.509528 | **0.606769（6）** | **0.562260（7）** | Best 指标当前最优 |
| M2（lr=5e-5） | 0.577223 / 0.541187 | 0.605426（2） | 0.558701（1） | 稳定提升，优于基线 |
| M3（uniform） | 0.564867 / 0.523611 | 0.593070（2） | 0.552115（3） | 小幅提升 |
| M4a（plain CE） | 0.526189 / 0.495613 | 0.579909（0） | 0.536512（4） | 对基线无明显优势 |
| M4b（focal） | 0.549825 / 0.519028 | 0.597368（3） | 0.552316（3） | 有提升但弱于 M1/M2 |

**消融结论（当前阶段）**：
1. **最有效方向**：有效 batch 提升（M1）与学习率调整（M2）贡献最大。  
2. **采样策略**：uniform 有增益但不如 M1/M2 稳定。  
3. **损失函数**：plain CE / focal 并未形成压倒性优势，仍需结合 Last 与曲线稳定性评估。  
4. **报告口径**：AP2 已明确存在 “Best > Last” 差异，后续论文将继续 **Best + Last 双口径**。

### 3.1 架构说明（已落地的总体形态）

已按规划形成“在线采集 + 推理服务 + LLM 编排 + 前端展示”的解耦架构：

- **采集端（Frontend）**：浏览器摄像头/麦克风采集、单次会话（开始-结束）组织、状态可视化

- **LLM 层**：`template/openai/ollama` 统一路由 + 失败回退  
- **展示层**：中文化 UI、调试信息、情绪标签与回复区域

### 3.3 ASR、LLM、前端三块关键技术细节（本周实做）

**ASR（从 mock 到真实）**
- 技术栈：`faster-whisper` + FastAPI 服务化  
- 接口形态：OpenAI 兼容 `audio/transcriptions`  
- 稳定性增强：低能量检测、双阶段解码 fallback、异常捕获、串行锁避免并发崩溃  
- 成果：ASR 文本已稳定回传前端，置信度字段可见

**LLM（从模板到可切换）**
- 技术栈：`requests` 调用 OpenAI 兼容接口 + Ollama 本地接口  
- 策略：`provider` 可切换，超时与异常自动回退 template，避免主链路阻塞  
- 成果：`llm_provider=ollama` 已成功返回真实生成文本

**前端（从调试页到演示页）**
- 技术栈：React、WebAudio、canvas 抓帧、WebSocket  
- 交互能力：录制波形、推理 loading、情绪颜色标签、回复气泡、调试展开/收起、事件时间线  
- 成果：演示可读性显著提升，非技术观众可直接理解流程状态
