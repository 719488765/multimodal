二、遇到的问题
--------------------------------------------------------------------------------

1. 训练崩溃
   - 现象：AP4 w005 在 epoch 28 训练阶段报错退出。
   - 报错：DataLoader worker 段错误（segmentation fault），主进程在 backward 阶段失败。
   - 伴随：BERT/Wav2Vec2 在 no_grad 下的 gradient checkpoint 警告。

2. 续训失败
   - 现象：从检查点恢复时优化器 state 加载失败（参数组数量与当前模型不一致）。
   - 原因：续训前更新了骨干冻结策略，与保存检查点时的优化器结构不一致。

3. 环境与依赖
   - HuggingFace 镜像 hf-mirror.com DNS 解析失败，影响模型元数据拉取（本地已有缓存可离线运行）。

4. 遗留项
   - AP3 two_stage 文档曾滞后（5/8 快照仅 28 行 val）；当前 metrics 已满 ep49。
   - AP4 主实验记录文档中 AP4 表格仍为占位。

三、修复策略
--------------------------------------------------------------------------------

1. 针对 DataLoader 段错误
   - 限制 OpenCV/BLAS 在 worker 内线程数，统一 DataLoader 安全参数。
   - 视频加载改为按帧索引采样，避免整片解码占满 worker 内存。
   - w005 配置将 num_workers 从 4 降为 2。

2. 针对续训与模型代码
   - 优化器/调度器加载失败时跳过并告警，仅用模型权重续训。
   - 冻结 BERT/Wav2Vec2 骨干，关闭 gradient checkpointing，消除无效反传警告。

3. 针对 AP4 流水线与集群环境
   - 新增串行脚本：w005 续训完成后自动依次跑 w010、w05lr、uniform、seed3407。
   - 在 tmux 会话 aseq_ap4_rest_serial 中单卡串行执行，避免七路并行 OOM。
   - 续训复用原日志目录名，保证 metrics 与 TensorBoard 连续。
   - 训练使用本地 HuggingFace 缓存（离线模式），规避镜像 DNS 问题。
